**이 문서는 작업이 끝나면 지운다.** 진행 중에만 의미가 있다.
사이트 동작에 대한 사실은 여기가 아니라 [`DESIGN.md §38`](DESIGN.md) 에 있다.

### 코드는 전부 코레일을 본다

- **`webview/KtxParserScript.kt`** — `SrtParserScript`(1359줄) 대체.
  `<table>` 전제와 "표 헤더로 열 찾기" 휴리스틱이 통째로 사라졌다. `li.tckList` 를 읽고
  좌석 상태는 **class 로만** 판정한다. 스크립트는 아홉 개다 (목록 분석 /
  1단계 / 1단계 확인 / 2단계 / 예약 결과 / 탭 확인 / observer / probe / 화면 종류).
  **재조회 버튼 탐색은 없다** — 갱신이 새로고침이 되면서 지웠다. (§38-9)
- **`webview/KtxLoginScript.kt`** — `btnGoLogin` / `btnGoLogout` 으로 판정. (§38-7)
  `logoutBtn` 과 `loginY` 는 **쓰지 않는다.** 테스트가 그 두 이름이 스크립트에
  들어가지 않는 것까지 확인한다.
  2026-08-29 실제 사이트(`/ticket/search/list`, 375px)에서 다시 재어 보니
  **머리말이 통째로 `display:none`** 이라 예전의 "보이는 것만" 조건 때문에 판정이
  언제나 `UNKNOWN` 이었다 = 로그인 확인이 죽어 있었다. 이제 **DOM 존재만** 본다.
  같은 폭에서 새 스크립트를 그대로 실행해 `LOGGED_OUT` 이 나오는 것을 확인했다.
- **`webview/KtxWebViewHost.kt`** — 갱신은 `reload()`(§38-9). DOM 서명 대상이
  `div.tckWrap`(= `SIGNATURE_SCOPES`), URL 기반 페이지 판정 제거,
  되돌리기 뒤 **목록이 실제로 보이는지 확인**.
- **2단계 예매** — `PageHost.clickReserve` 가 `selectSeat`(1단계) + `confirmReserve`(2단계)로
  갈라졌다. 상태 표현도 함께 갈라졌다:
  `WatchState.SEAT_SELECTED`(좌석만 골라 둠) / `ReserveStage`(SELECT·CONFIRM).
- `Srt*` → `Ktx*` 이름, UI·알림 문구, `START_URL` 전부 코레일로.
  살아 있는 코드에 `Srt` 로 시작하는 이름은 없다. 남은 "SRT" 는 **비교·역사 서술**뿐이다.

단위 테스트 102건 통과. `cd android && ./gradlew --offline :app:testDebugUnitTest`
debug APK 빌드도 통과.

## 남은 일

### 1. 실기기 확인 ★ 지금 제일 중요한 것

여기까지는 **실측 덤프를 보고 쓴 코드**다. 실제 WebView 에서 한 번도 돌려 보지 않았다.
`chrome://inspect` 로 DOM 을 보면서 순서대로 확인한다.

0. **로그아웃 상태로 감시 시작** → "먼저 코레일에 로그인하세요" 가 뜨고 시작되지 않는가.
   로그인한 뒤에는 그냥 시작되는가. 로그에 `LOGIN_STATE LOGGED_OUT/LOGGED_IN` 이 남는다.
   (로그인 상태의 `a.btnGoLogout` 은 아직 실제 사이트에서 못 봤다 — 덤프로만 확인했다)
0-1. **감시 중에 로그아웃해 본다** (다른 탭에서든, 세션이 풀리기를 기다리든).
   다음 사이클에 `LOGIN_STATE LOGGED_OUT` → 감시가 멈추고 "세션 만료" 카드와
   알림이 뜨는가. 확인은 사이클마다 도는 DOM 읽기라 요청이 늘지 않는다. (§27-1)
0-1. **로그아웃 상태로 앱 실행** → 메인이 뜬 직후 `/ticket/login` 으로 넘어가는가. (§27-2)
   로그에 `LOGIN_REDIRECT` 가 남는다. 확인할 것 셋:
   - 메인 화면의 머리말에도 `a.btnGoLogin` 이 있는가 (실측은 `/ticket/search/list` 에서만 했다).
     없으면 판정이 `UNKNOWN` 이라 **보내지 않고 그대로 둔다** — 실패가 아니라 설계다.
   - 로그인한 뒤 사이트가 메인으로 돌려보낼 때 **다시 로그인으로 튕기지 않는가** (되튐).
   - 조회 결과 화면에서는 **절대** 넘어가지 않는가. 넘어가면 조회 조건이 날아간다.
1. 조회 결과 화면에서 [열차 선택] 목록이 채워지는가 (편성·번호·시각·좌석 상태)
2. 감시 시작 → **새로고침(F5)** 이 나가고 목록이 다시 그려지는가 (§38-9)
   - 조회 조건(구간·날짜·시각·인원)이 새로고침 뒤에도 그대로인가
     → 안 그대로면 `localStorage["LS_TICKET_GENERAL"]` 부터 본다
   - `researchSettleMs`(12초) 안에 목록이 다시 그려지는가
     → `PAGE_SETTLE_TIMEOUT` 이 계속 뜨면 이 값을 늘린다. **간격이 아니라 이 값이다**
2-1. **접속 대기열이 걸렸을 때** (§39). 사람이 많은 시간대에 한 번 겪어 봐야 한다.
   - 대기 화면이 떠 있는 동안 로그에 `PAGE_WAIT_START` → `PAGE_WAIT_TICK` 이 쌓이고,
     **`RESEARCH_TRIGGERED` 가 그 사이 한 줄도 없어야 한다.** (있으면 대기 순번이 날아간다)
   - 대기가 풀리면 `PAGE_WAIT_DONE=TRAIN_LIST …` 가 뜨고 그대로 판정으로 이어지는가.
   - 화면에 `화면을 기다리는 중입니다… N초` 가 갱신되는가 (멈춘 것처럼 보이면 안 된다).
   - 3분(`pageWaitMs`)을 넘겨서 `PAGE_WAIT_TIMEOUT` 이 나면, 그때 화면이 정말
     무엇이었는지 `chrome://inspect` 로 확인한다. **대기 화면이 맞다면 그때 비로소**
     NetFunnel 마커를 `KtxSelectors` 에 넣을 값어치가 생긴다 (지금은 실측이 없어 안 넣었다).
3. 좌석이 열렸을 때 1단계로 그 칸이 골라지는가 (`active` 가 붙는가)
4. 하단 바가 뜨고 2단계 [예매] 가 눌리는가
   - 여기서 대기가 걸리면 `confirmTimeoutMs`(90초)까지 기다린다. 6초에 포기하던
     예전 동작이면 좌석을 놓쳤을 자리다. (§39-6)

로그(`RESEARCH_TRIGGERED` / `PAGE_UPDATED` / `RESERVE_CLICKED` /
`RESERVE_SEAT_SELECTED` / `RESERVE_HANDOVER`)에 각 단계가 그대로 남는다.
실패하면 로그의 `reason` 을 보고 `KtxSelectors` 를 고친다.

**짧은 간격으로 반복하지 말 것.** 대원칙 2. 새로고침은 예전 AJAX 재조회보다 훨씬 무겁다.

### 1-1. 역/지역 선택 창이 안 뜬다 (원인 확정 — `100vh`. 고침, 실기기 확인 대기)

실기기에서 출발역/도착역을 눌러도 아무 반응이 없다는 보고가 있다.

브라우저에서 375×812 로 재현해 본 결과 **사이트 쪽은 정상**이다. 이 창은
`window.open` 팝업이 아니라 `document.body` 에 붙는 react-modal 이고
(`div.ReactModalPortal` → `position:fixed`, z-index 1005), 오버레이 rect 도 뷰포트를
정확히 채운다. → §38-10

즉 **앱이 "위로 띄워" 줄 수 있는 종류의 창이 아니다.** `KtxPopupHost` 도 `PopupOverlay` 도
관여하지 않는다. 남은 가능성은 WebView 안의 JS 다. 그래서 `onConsoleMessage` 로
JS 오류/경고를 로그 창(`PAGE_CONSOLE`)에 흘리도록 해 두었다.

#### 사이트 번들을 뜯어 보니 원인이 넷이다 (2026-08-29)

버튼은 `<a href="#none">` + React `onClick` 하나뿐이고, 그 핸들러는
`e.preventDefault()` 뒤에 `stationDisabled` 를 보고 창을 연다. → §38-10

그래서 "아무 반응 없음" 이 넷으로 갈린다. **화면에서는 넷이 전부 똑같아 보인다.**

1. 탭이 그 `<a>` 에 닿지 않았다 (무언가 덮고 있다)
2. 닿았지만 이벤트가 React 까지 가지 못했다
3. 갔지만 `stationDisabled` 라 사이트가 조용히 무시했다 — **오류도 로그도 남지 않는다.**
   `PAGE_CONSOLE` 만 보고 있으면 영원히 못 찾는 경로가 이것이다
4. 창은 만들어졌는데 보이지 않는다

#### 그래서 [역 진단] 을 넣었다

로그 창에 **[역 진단]** 버튼이 있다. (`STATION_PROBE`, 읽기 전용 — 요청이 나가지 않는다)

**확인 순서:** 재현 화면에서 로그 창 열기 → **[역 진단]** → 역 버튼을 손으로 눌러 봄
→ **[역 진단]** 다시. 두 번째 줄이 위 넷 중 어느 것인지 알려준다.
읽는 법은 §38-10 의 표에 있다.

3번(`핸들러=돎 모달=0→0`)이면 앱이 고칠 것이 없다. 사이트가 그 화면에서 역 변경을
막아 둔 것이므로, 구간을 바꾸려면 메인 화면에서 다시 조회해야 한다.

#### 1차 진단 결과: **4번으로 확정** (2026-08-29)

실기기 로그에서 `모달=1` 이고 맨 위 모달 본문에 역 목록이 다 들어 있었다.
**창은 만들어진다.** 1·2·3번은 전부 탈락이고, 남은 것은 "왜 안 그려지는가" 뿐이다.
→ §38-10

같은 줄에서 **뷰=411x449** 도 나왔다. 브라우저로 재현했던 375×812 보다 훨씬 납작하다.
앱이 WebView 위아래로 UI 를 얹기 때문인데, 모달이 뷰포트 높이에 기대고 있다면
여기가 갈라지는 지점일 수 있다. 아직 추측이다.

`맨위="…"` 에 안내 문구가 찍히면 매크로 감지(`CODE : -8002`) 모달일 수 있다.
그 상태에서는 역 버튼뿐 아니라 아무것도 눌리지 않는다. (실측 중 실제로 걸렸다)

#### 2차 진단: **높이가 0. 원인은 `100vh`** (2026-08-29)

`모달 [0,0,411,0]` — 폭은 411 로 꽉 차는데 높이만 0 이다. 덮인 것도 투명한 것도
아니고 조상에 `transform` 도 없다. **`window.innerHeight` 는 460 인데 `100vh` 만 0** 이다.

크롬 덤프(닫힘/열림, 메인/조회결과 네 벌)를 대조해 이유가 확정됐다. 오버레이에는
인라인 기하가 **하나도 없다** — react-modal 이 `overlayClassName` 을 받으면 기본
인라인 스타일을 붙이지 않는데 코레일이 그렇게 쓴다. 안쪽 `Content` 는
`position:static` 이라 크기를 만들지 못한다. 즉 이 창의 크기는
`.layerPopup { height:100vh }` **하나에 전부 달려 있고 대체 경로가 없다.** → §38-10

#### 고쳤다 — 확인 대기

두 겹으로 막았다. (→ §38-10)

1. **문서를 받는 시점**: `KtxWebViewHost.loadStartUrl` 이 WebView 가 화면에 붙어
   높이를 얻을 때까지 기다린다. 설정 화면의 [시작 페이지로] 도 같은 경로였다.
2. **결과 확인**: `onPageFinished` 마다 `100vh` 를 직접 재서 `innerHeight` 와 어긋나면
   `.layerPopup` 높이를 픽셀값으로 덮어쓴다. 멀쩡하면 아무것도 하지 않는다.

**확인 방법:** 앱을 다시 설치하고 로그 창을 연다.

- `VIEWPORT_FIX=보정함 100vh=0 → 460px` → 1 이 여전히 새고 있지만 2 가 막았다.
  역 창이 뜨는지 확인.
- `VIEWPORT_FIX=손대지 않음(ok) 100vh=460 innerHeight=460` → `vh` 는 정상이다.
  그래도 창이 안 뜨면 **원인이 다른 곳**이다. [역 진단] → 역 버튼 → [역 진단] 으로
  `모달 [x,y,w,h]` 를 다시 본다.
- `VIEWPORT_FIX` 줄 자체가 없으면 `onPageFinished` 가 오지 않은 것이다.

### 2. 실측이 더 필요한 것 (§38-8)

**추측으로 채우지 말 것.** 확인되면 `KtxSelectors` 의 해당 상수부터 고친다.

- 예약 실패 시 실제 문구 — `RESERVE_FAILED_MARKERS` 는 지금 **SRT 값 그대로**다
- 조회 폼의 출발일 입력 — `SEARCH_DATE_FIELDS` 를 **비워 뒀다.**
  그래서 상단 요약에 날짜가 빠진 채로 보인다 (표시용이라 감시에는 영향 없음)
- 아무 칸도 안 고른 상태에서 `div.ticket_reserv_wrap` 이 DOM 에 아예 없는지, 숨겨져만 있는지
- ITX·무궁화가 섞인 결과에서 `flag_wrap` class 가 어떻게 달라지는지
- 자유석/입석이 별도 `price_box` 로 나오는지
  (안 나온다면 `SeatClass` 를 일반실/특실 2개로 유지할 수 있다 — **큰 파급을 피한다**)
- SPA 에서 뒤로 가기가 조회 결과 화면으로 돌아가는지

  반복 테스트하지 않는다. 실패 경로에 자동 재시도를 넣지 않는다 (대원칙 2)

- 세션 밖(Android Studio)에서 파일이 바뀌는 일이 잦다. **덮어쓰기 전에 다시 읽는다**
- `WatchControllerTest` 에서 `advanceUntilIdle()` 금지. `runCurrent()` / `advanceTimeBy()`
