# Catch Train — 크롬 확장

같은 목적의 PC 판. 코레일 조회 결과 화면을 감시하다가 체크해 둔 칸이 열리면 알리고
그 칸을 골라 [예매] 를 눌러 준다.

**M4 까지 코드가 있다.** 팝업에서 칸을 체크하고 [감시 시작] 을 누르면 사이클마다 탭을
새로고침하며 그 칸이 열리는지 보다가, 열리면 알리고 **좌석 칸(1단계) → 하단 [예매](2단계)**
까지 눌러 준다. **결제는 사람이 한다** (대원칙 3).

**다만 실제 코레일에 대고는 아직 한 번도 안 눌러 봤다.** 검증은 모형 DOM 까지다
([`test/browser/`](test/browser/)).

확장에는 진짜 터치가 없어서 클릭은 `el.click()`(= `isTrusted=false`) 하나뿐이다.
그래서 **누른 뒤에 반드시 확인한다.**

```
좌석 칸 click()  →  그 칸에 active 가 붙었나?
   ├ 붙음   → 하단 바 [예매] (문구 완전일치) → 화면이 넘어갔나? → 끝. 결제는 사람이
   └ 안 붙음 → 멈추고 사람을 부른다. 다른 방법으로 또 누르지 않는다
```

확인이 어긋나는 자리는 전부 **인계**로 끝난다 — 좌석만 골라 둔 채 알림을 띄우고 멈춘다.
그래서 "모르는 사이에 엉뚱한 것이 눌리는" 경로가 없다.

**끄는 스위치는 없다.** 좌석이 열리면 그 칸을 고르고 [예매] 까지 누르는 것이 이 도구가
하는 일이라, 설정으로 두지 않는다. 위의 인계 규칙이 그 자리를 대신한다.

사이트로 **요청**이 나가는 자리는 여전히 새로고침 하나뿐이다
(`background/page-host.js` 의 `requery`). 1·2단계 클릭은 화면 안에서 끝난다.

페이지를 누르는 코드는 셋뿐이다 — `content/ktx/reserve.js` 의 1·2단계, 그리고 팝업의
**[클릭 진단]**(M-a 실측). 진단은 **감시가 아니라 사용자가 두 번 눌러야만** 돌고,
좌석 칸 하나를 누를 뿐 [예매] 는 건드리지 않는다.
아래 [실측](#지금-할-일--클릭-진단-m-a) 참고.

남은 단계는 [`PLAN.md`](PLAN.md) §E-9.

## 쓰는 법

`chrome://extensions` → `개발자 모드` → `압축해제된 확장 프로그램을 로드` → 이 폴더.

1. 코레일에서 **직접** 원하는 조건으로 조회한다. (조회 조건은 확장이 갖지 않는다 — 대원칙 4)
2. 툴바의 확장 아이콘을 눌러 팝업을 연다. 그 탭의 조회 결과가 목록으로 뜬다.
3. 원하는 (열차 × 좌석등급) 칸을 체크한다. 매진인 칸도 체크할 수 있다 —
   **지금 매진인 좌석이 풀리기를 기다리는 것이 이 도구의 목적이다.**
4. [감시 시작]. 좌석이 열리면 알림이 뜨고 감시가 멈춘다. **예매는 사람이 한다.**

감시 패널의 **간격** 줄을 펼치면 주기를 바꿀 수 있다. 오른쪽의 **"분당 약 N회"** 가
실제로 코레일에 나가는 요청 수이고, **봐야 하는 것은 그 숫자다.** 간격만 보면
"0.3초니까 괜찮겠지" 로 읽히지만 한 사이클의 대부분은 새로고침 자체(약 1초)라,
대기를 두 배로 늘려도 요청 수는 절반이 되지 않는다. 실제로 물러서려면 상한(3초) 쪽으로
가야 한다 — 그러면 분당 15회다. 차단을 부르는 것은 간격이 아니라 분당 요청 수다
(대원칙 2, SRT IP 차단은 실제로 있었다). 바꾼 값은 **다음 [감시 시작] 부터** 적용된다.

확장을 새로 로드했다면 코레일 탭도 한 번 새로고침해야 content script 가 붙는다.

시작을 막는 경우가 셋 있다 — 체크한 칸 없음 / 다른 탭에서 이미 감시 중 /
**비로그인**. 코레일은 비로그인에서도 조회가 되어서, 그대로 두면 좌석이 열린 바로 그
순간에 로그인 화면으로 튕긴다 (§27-1).

비로그인은 **누르기 전에 막는다.** [감시 시작] 이 잠기고 이유가 뜨고,
[코레일 로그인 화면 열기] 가 **새 탭**을 연다 — 보고 있던 탭의 주소를 갈아 끼우면
조회 조건이 날아간다. 로그인한 뒤 팝업을 다시 열면 잠금이 풀린다.
단 판정이 `UNKNOWN` 이면 **잠그지 않는다** (대원칙 6). service worker 쪽 확인은
그대로 남아 있다 — 팝업이 아는 로그인 상태는 마지막으로 읽은 시점의 것이라 낡을 수 있다.

무슨 일이 있었는지는 팝업 아래 **[로그 보기]** 에 남는다. 특히 접속 대기열에 걸렸을 때
`PAGE_WAIT_START` 가 쌓이는 동안 **`RESEARCH_TRIGGERED` 가 한 줄도 없어야 한다** —
대기 중에 새로고침하면 대기 순번이 날아간다. (§39-7)

테스트는 Node 내장 러너로 돈다. 의존성이 0 이라 `npm install` 이 없다.

```bash
cd extension && node --test test/
```

## 지금 할 일 — [클릭 진단] (M-a)

M3(좌석 칸 고르기)을 붙이기 전에 **답해야 하는 질문이 하나** 남아 있다:
확장이 만드는 클릭은 `isTrusted=false` 인데, **코레일이 그것을 보는가.**
보지 않으면 그냥 눌러도 되고, 보면 `chrome.debugger` 밖에 길이 없는데 그쪽은 상시 배너와
매크로 감지(§38-10) 위험이 딸려 온다. **추측으로 정하면 첫 실사용에서 좌석을 날린다.**

재는 방법 — 조회 결과 화면에서 팝업을 열고 **[로그 보기] → [클릭 진단]**, 그리고 한 번 더.

- **예약 가능한 좌석이 있는 조회 결과**에서 해야 한다. 매진 칸은 눌러도 원래 아무 일이
  없어서 "안 통했다" 와 구분되지 않는다.
- 진단은 좌석 칸 **하나를 실제로 누른다.** [예매] 는 누르지 않는다.
  끝나면 그 칸이 골라진 채로 남는다 — 되돌리려면 페이지를 새로고침하면 된다.
- devtools 를 열 필요가 없다. 나간 요청도 진단이 같이 세어 준다.
- **한 번만 한다.** 결과가 나쁘다고 다른 방법으로 또 누르지 않는다 (대원칙 2).

결과 한 줄(`SYNTHETIC_OK` / `NO_EFFECT` / …)이 무엇을 뜻하는지와 **적어 둘 자리**는
[`../docs/DESIGN.md`](../docs/DESIGN.md) §38-8 에 있다. 사이트에 대한 사실은 한 벌만 둔다.

## 구조

```
src/
├── background/   service worker — 상태와 결정
│   ├── index.js          라우팅 · 탭 수명 · alarms 부활 그물 · 저장
│   ├── watch-controller.js  ★ 감시 루프 전체. **chrome API 를 하나도 모른다**
│   ├── page-host.js      chrome API 가 끊기는 자리. 새로고침은 여기 한 곳뿐
│   ├── watch-config.js   루프 파라미터. 값마다 근거가 주석에 있다
│   ├── watch-state.js    상태·오류. 팝업은 이 값만 본다
│   ├── scheduler.js      간격(무작위) · sleep(AbortSignal)
│   ├── logger.js  notifier.js  store.js
├── content/      DOM 판독 팔
│   ├── early.js          document_start. 스크롤 되살리기 끄기 하나뿐
│   ├── index.js          진입 (import() 로 아래를 부른다)
│   ├── ktx/{selectors,dom,parse,page-kind,login,query}.js   판독 (읽기만)
│   ├── ktx/tap.js         누르는 일의 바탕. **아래 둘이 같은 방법으로 누르게** 하는 곳
│   ├── ktx/reserve.js     ★ 1단계(좌석 칸) · 2단계([예매]). **감시가 누르는 유일한 자리**
│   └── ktx/probe.js       ★ M-a 실측. 감시 경로 밖이고 사용자가 두 번 눌러야 돈다
├── domain/       ★ chrome API 도 DOM 도 모르는 순수 코드 (안드로이드 domain/ 과 같은 규칙)
└── ui/           팝업
test/             node --test. 안드로이드 단위 테스트를 그대로 옮긴 것이다 (§34-2)
test/browser/     DOM 이 있어야 하는 것들. **Node 가 없는 머신에서 실제로 돌려 볼 수 있는 유일한 검사**
```

- **content script 는 판독이 기본이다.** 무엇을 언제 할지는 service worker 가 정한다.
  누르는 것은 `reserve.js`(감시)와 `probe.js`(사용자가 부르는 진단) 둘뿐이고,
  그 밖에 페이지를 건드리는 것은 `SCROLL_TOP` 하나 — 그것도 스크롤 위치다.
- **누른 뒤에는 반드시 확인한다.** `el.click()` 은 `isTrusted=false` 라 사이트가 무시할 수
  있다. 확인이 어긋나면 **다른 방법으로 또 누르지 않고 사람에게 넘긴다** (§E-2-3).
  이 규칙이 깨지면 `test/browser/reserve.html` 이 먼저 알려 준다.
- **`watch-controller.js` 는 `chrome.*` 를 부르지 않는다.** 그래서 브라우저 없이 통째로
  테스트된다. 확장 API 는 `page-host.js` 와 `index.js` 에서만 쓴다 (§34-1).
- **selector 는 `content/ktx/selectors.js` 한 곳에만.** 팝업도 SW 도 selector 를 모른다.
- 선언된 content script 는 ES 모듈이 아니라서 `content/index.js` 가 `import()` 로 나머지를
  불러온다. 그래서 그 모듈들이 manifest 의 `web_accessible_resources` 에 있다.
- **빌드 도구를 두지 않는다.** 순수 ES 모듈이면 번들러 없이 돈다.
- 권한은 **그 단계에서 실제로 쓰는 것만** 넣는다. 지금은 `storage`·`notifications`·`alarms`
  와 코레일 host permission 이다. `offscreen`(알림 소리)은 결제 재촉과 함께 M4 에,
  `debugger` 는 실측 뒤에 **선택 권한**으로 (PLAN.md §E-2, §E-8).
  `alarms` 는 **감시 주기가 아니다** — 최소 30초라 그럴 수 없고, service worker 가 죽었을
  때를 위한 부활 그물이다 (§E-3-2).
- 저장소는 **`storage.session` 이 기본**(감시 상태·선택·로그)이고, **`storage.local` 은
  감시 간격 하나뿐**이다. 대원칙 4 가 저장을 금지한 것은 조회 조건과 체크한 칸이지
  설정이 아니다.

## 안드로이드와 갈리는 지점

### 정해진 것

| | 결정 | 근거 |
|---|---|---|
| 감시 주기 | **service worker** 에서. 상태는 `chrome.storage.session` | PLAN.md §E-3 |
| 간격 기본값 | **0.3~0.5초 + 팝업 슬라이더.** 안드로이드(0.1~0.3초)와 다르다 — 그 값은 갱신이 AJAX 이던 SRT 시절 것이다 | §38-9 |
| 간격 저장 | 여기만 `chrome.storage.local`. 설정이라 브라우저를 닫아도 남아야 한다 | `store.js` |
| 갱신 | **`chrome.tabs.reload`.** PC 폭에서 [열차조회] 가 보여도 누르지 않는다 | PLAN.md §E-4 |
| 클릭 | `ClickDriver` 를 갈아 끼우는 이음매로 두고 **실측으로** 고른다. 다 막히면 **사람에게 인계** | PLAN.md §E-2 |
| 빌드 도구 | 두지 않는다 | 위 구조 |
| selector 공유 | 지금은 이 폴더에 미러, `shared/` 승격은 M5 | PLAN.md §E-8 |

### 안 가져오는 것

- **비로그인일 때 로그인 화면으로 스스로 이동**(안드로이드 §27-2). 사용자의 탭은 사용자의
  것이고, 확장이 조용히 주소를 갈아 끼우는 것은 브라우저에서 명백히 적대적인 동작이다.
  팝업의 버튼으로만 연다. (PLAN.md §E-6-5)
- **`100vh` 보정**(§38-10). WebView 가 높이를 얻기 전에 문서를 받는 안드로이드 고유의 사고다.

### 제약은 약해져도 풀지 않는다

확장은 백그라운드 탭에서도 DOM 을 읽을 수 있다. **그렇다고 제약을 풀지 말 것** —
사람이 보지 않는 채로 도는 감시가 바로 대원칙 2 가 막으려던 그 요청이다.
탭이 살아 있어야 한다는 선은 유지한다.
